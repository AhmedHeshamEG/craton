# P11 — The viable test: Field 2's heart

## TLDR

Field 2 starts with its heart: attention that **counts**, so it starts out as ETAS (the standard
aftershock model) and only learns what ETAS misses. P11 asks whether that heart, trained on four
regions, beats ETAS in a region it never read (CB-32).

It ran twice and lost twice. The first heart re-weighed every past quake by its age, size and
distance, and nothing else: −0.25 bits per quake with the region's ETAS numbers as context, +0.007
without. Its query was empty: a place couldn't say "I'm busy right now".

The rebuilt heart gives every place a **learned state** that its quakes write into, lets places
read their neighbours, and learns from days that ETAS was fitted *before*, as the test does. Its
lean first pass (one member, seed 0) scores **−0.044** on CB-32 (the Field: +0.336), so the stop
rule fired again. Look inside, though, and it's a mixed loss, not an empty one. In California the
state nearly doubled ETAS's count and hit what came (El Mayor 92%, Ridgecrest 100%). In Japan it
turned ETAS *down* while ETAS was already three times short. Which way it learned depends on
the region it used to decide when to stop.

## The idea, step by step

**1. What ETAS already is.** Every past quake sends some aftershocks into the future. How many
depends on its size; when they come follows Omori's law (fast at first, then slower); where they
land follows a bump around it. Tomorrow's rate in a place = the background + the sum of what every
past quake sends there.

**2. That's attention.** In a transformer each word (a *query*) looks at every other word (the
*keys*) and takes a weighted mix of them. Swap words for places and quakes: each place looks at
every past quake and takes a weighted *sum*. ETAS is an attention layer whose weights are fixed by
eight numbers.

**3. A sum, not a share.** A transformer's weights are a softmax: they add up to one. Ten keys or
a thousand, you get a mix. Earthquakes don't work like that. Ten overlapping aftershock sequences
make about ten times the quakes. So Field 2's heart uses *counting* attention: the weights don't
have to sum to anything.

**4. Born as ETAS.** The heart keeps ETAS's weights and multiplies each one by a learned factor,
e^h. The network that makes h ends in a layer that starts at exactly zero, so at step 0 every
factor is one and the heart *is* ETAS, number for number. It can't start worse than the textbook.

**5. The first heart, and why its query was empty.** It read each quake in bins: age on a log
clock, size, distance in the quake's own rupture length. Each bin got one weight. That's a
better-shaped kernel, but every place still hears the same thing from the same quake. On the test
sequences ETAS's miss is all in *how many* (central Italy 2016: 583 expected, 1,065 came; Tohoku
1,129 and 3,478). *Where* barely moved. A heart that can't say "this place is running hot" can't
fix that.

**6. Three more things went wrong in the first run.** Each tile's ETAS was fitted on the same
days the heart learned from, and a fitted model gets its own totals right, so the miss was
invisible in training. The region's ETAS numbers, given as context, were learned on three regions
and extrapolated on the fourth (it cut central Italy's count to 230). And it heard nothing below
completeness, with places that never saw each other.

**7. A query with content.** The rebuilt heart gives every place a small state (eight numbers).
Every quake that lands in the place, down to half a magnitude below completeness, writes into it.
How much it writes depends on the quake's size and age, and both are learned, so the writing fades
however the data says it should. Divided by what the place's background would have written, the
state reads as "how busy is this place, compared with usual". Then places read the average state
of the cells around them (3 × 3 and 9 × 9) for two rounds. The state then bends every message the
place receives: a busy place can hear yesterday's quakes louder.

**8. Rulers, not context.** No region's ETAS numbers go in as inputs. Instead they set the units:
time in the region's own Omori c, the state in the place's own background, size above
completeness, distance in rupture lengths. That's dimensional analysis doing the job an address
would do.

**9. Train as tested.** The test fits ETAS on a region's past and asks about the year after. So
the training days are now held the same way: each tile's days are cut into two-year blocks, and
each block is forecast by an ETAS fitted only on what came before it. That's 214 blocks and 64,414
tile-days. One rule copied from the benchmark: a block counts only if its ETAS was fitted on at
least 200 quakes (fitted on fewer, ETAS often comes out explosive).

**10. The check before building.** Before training anything, `craton screen` measured how much
each piece of information explains ETAS's miss in a region left out (next section). The
expectation was written down and committed before the first rebuilt heart trained.

**11. Stopping on a region it doesn't learn from.** A model that stops training when it does best
on its own regions has learned to memorise them. CB-32 asks about a region it never read. So each
member sets one training region aside and stops when it does best there.

## The LLM analogy

The first heart was attention with an empty query: every token's question was the same, so the
answer could only depend on the keys. The rebuilt heart gives each token a hidden state, like a
recurrent network's, written by what it has seen, and lets tokens talk to their neighbours, like a
local attention window. "Train as tested" is the oldest rule in machine learning (train on the
distribution you'll be scored on). Here it became concrete: the error you need to learn only
exists on days the base model never saw.

Where the analogy breaks: in language there's one way to hold the training data out. Here there are
four regions, and *which one* a model stops on turned out to decide what it learned.

## What the code does

- `craton/field2/tested.py`: the world pool held as tested. Every tile's days are cut into
  two-year blocks (origins), each with its own ETAS fitted before it and its own kernel pieces. The
  quakes the place state hears (from mc − 0.5) are stored once per tile.
- `craton/field2/screen.py` (`craton screen`): ETAS's miss on that pool, and a tiny correction
  fitted on three regions and scored on the fourth, for each candidate piece of information.
- `craton/field2/place.py`: the rebuilt heart (`PlaceHeart`). The place state (`state`), the
  neighbour rounds, the bin weights bent by the state, the smooth clock, the additive head, and
  the optional ETAS-excitement inputs. Every part has its own switch in `HeartNet`; all off is the
  first heart.
- `craton/field2/learn.py`: training as tested. Members rotate the region they set aside to stop
  on, and the loss is a Poisson likelihood per quake.
- `craton/field2/world.py`, `npp.py`: the same heart asked about any box (CB-32) and about
  EarthquakeNPP's grid (CB-29).
- `configs/field2/place.yaml` (four members) and `place_lean.yaml` (the lean pass: one member).
- `scripts/ablations/field2_heart.py`: train the folds, score CB-32 and CB-29, record each member's
  learning and stopping regions in `results/ablation/field2_heart.json`.

## The numbers

**The check** (`results/ablation/field2_heart.json` and `field2_screen.json`). On the pool held as
tested, ETAS's miss runs both ways: it over-counts California (came ÷ expected 0.76, 0.57 at
M ≥ mc + 1) and New Zealand (0.89, 0.66), under-counts Japan (1.15) and gets central Italy right
(1.01). Bits per quake at mc + 1, fitted on three regions, scored on the fourth:

| Information | Gain |
|---|---|
| the place's own quakes | −0.000 |
| + the small ones below completeness | −0.060 |
| + the neighbours' (what the state can learn) | −0.055 |
| + how excited ETAS is | +0.010 |
| the region's ETAS numbers alone | **−4.40** |
| the Field's 54 counters | −0.154 |
| *yardstick: came ÷ expected, never an input* | *+0.168* |

The region's ETAS numbers as an input are a disaster in a region left out, which explains the
first run. The state's information transfers almost nothing on the pool, while the yardstick says
there's +0.17 to win. But the Field's own counters score −0.15 here and +0.34 on CB-32, so the pool
undersells the test sequences. Written before training: CB-32 between −0.05 and +0.15, centre
+0.05; CB-29 a tie.

**The three answers.**

| | First heart (seed 0) | Rebuilt heart, lean pass (one member, seed 0) | The Field (3 seeds) |
|---|---|---|---|
| Born equal to ETAS? | yes: 0.000 on all 8 sequences, 7.256 on CB-29 | yes (the suite holds it to 10⁻⁵) | n/a |
| CB-32 (bits per quake over ETAS) | −0.248 with context, +0.007 without | **−0.044** | +0.336 |
| CB-29 (lower is better; their ETAS 7.256) | 7.250 (without context) | 7.260 | 7.167 |
| Above ETAS on every seed? | no | no (one seed, one member) | yes |

The lean pass is one member and one seed. It's a first look, never a final score. The rule for it
was: if it loses, stop, so no more seeds or members were trained.

**Per sequence** (figure `docs/assets/field2-heart-*.png`): quakes expected as a share of those
that came.

| Sequence | ETAS | Rebuilt heart | Bits | Its member stopped on |
|---|---|---|---|---|
| Central Italy 2016-17 | 55% | 60% | +0.05 | California |
| L'Aquila 2009 | 22% | 24% | +0.07 | California |
| El Mayor 2010 | 48% | **92%** | **+0.20** | central Italy |
| Ridgecrest 2019 | 49% | **100%** | **+0.11** | central Italy |
| Tohoku 2011 | 32% | 27% | −0.37 | California |
| Kumamoto 2016 | 55% | 40% | −0.41 | California |
| Darfield 2010 | 64% | 64% | 0.00 | California |
| Kaikoura 2016 | 76% | 76% | 0.00 | California |

**What happened.** Every member chose its stopping region by the same rule (the first one
alphabetically that it didn't learn from), so three of the four folds stopped on California. On
California's pool, ETAS fitted on the past over-counts the next two years. A heart that turns ETAS
down does best there, so that's what got kept. The fold that stopped on central Italy (where ETAS
fitted on the past is right on average) kept a heart that turns ETAS *up* when a place is busy, and
that heart counted El Mayor and Ridgecrest almost exactly. New Zealand's fold found nothing on
California at all and stayed ETAS.

So the state *can* carry the signal. The fold that stopped on Italy learned the right rule; the
folds that stopped on California learned the opposite one. Picking where to stop isn't neutral.
The four-member version spreads stopping over three regions and averages them, but it wasn't run:
the lean pass lost, and the stop rule fired.

## Try it yourself

```bash
uv run --no-sync python -m pytest tests/test_field2.py -q             # born as ETAS, both hearts
uv run --no-sync craton screen                                         # the check (~10 min after the origins exist)
uv run --no-sync python scripts/ablations/field2_heart.py train place_lean 0   # five hearts, ~45 min on a 2060
```

Building the origins the first time takes about an hour (ETAS refitted 214 times).

## Check yourself

<details><summary>Why can't a softmax head count aftershocks?</summary>
Its weights always sum to one, so a place next to one sequence and a place next to ten
overlapping ones get the same total. The count lives in the sum, and a softmax throws the sum
away.</details>

<details><summary>Why did training on the days ETAS was fitted on hide the miss?</summary>
A maximum-likelihood fit matches the number of quakes it was fitted on. On those days ETAS's
total is right by construction, so there's no "how many" error left to learn, and the test is
all "how many".</details>

<details><summary>Why is a running came ÷ expected ratio a yardstick, not an input?</summary>
It's ETAS's error, handed in by hand. A model fed it would learn to repeat it, not to understand
why places get busy. The state has to work that out from the quakes alone; the ratio only says
how much there was to find.</details>

<details><summary>How can the stopping region change the sign of what a model learns?</summary>
Early stopping keeps the version that scores best on the stopping days. If on those days the
base model over-counts, every step that turns it down looks good and gets kept, and the same
step hurts a region where the base model under-counts.</details>

<details><summary>Why measure time in the region's Omori c and not in days?</summary>
Because c is how fast aftershocks start decaying there. One day in a region with a short c is
"late" and in another "early". In units of c, the same weight means the same thing everywhere, so
nothing about the place has to be said.</details>

## Glossary

- **Counting (additive) attention**: attention whose weights are summed, not normalised.
- **Born as ETAS**: the learned part starts at zero, so the untrained model equals ETAS.
- **Place state**: a few numbers per place, written by the quakes that fall in it, learned.
- **Train as tested**: training days forecast the way the test forecasts them: by an ETAS that
  never saw them.
- **Origin**: one block of days and the ETAS fitted before it.
- **Yardstick**: a measurement of what there is to win, never given to the model.
- **Lean pass**: one member, one seed, run first; the rest only if it wins.
- **Fold**: one run of a leave-one-region-out test; the model never read the region it's scored on.
- **Stopping region**: the region whose days decide when training stops.
