# P3 — The test before the model: CratonBench v1

## TLDR

Before Craton trains anything, it decides how it will be judged. P3 freezes four tests (CB-01 … CB-04),
cuts the training data so that no test answer can sneak in, and scores the simple methods every model
has to beat: climatology, a Poisson rate, ETAS (the standard aftershock model) and inverse-distance
weighting for GPS.

The floor, now on the scoreboard: ETAS forecasts the 2016-17 Apennines sequence with **−7.12 bits per M3+
quake**, against **−14.64** for a model that ignores aftershocks. A hidden GNSS station can be rebuilt from
its neighbours to **17.8 mm**. A masked measurement costs climatology **22.7 bits**. Craton-mini (P4)
starts from these numbers.

## The idea, step by step

**1. Build the test first, or you'll fool yourself.** Train a model, look at the result, tweak, look
again: after a few rounds the "test" has quietly become training data, because you chose the tweaks that
looked good on it. LLM labs freeze their evaluation sets before training for this reason. Craton does
it in P3, before a single weight exists.

**2. Hold out what you most want to know about.** Two eras are held out of training forever: era A,
24 August 2016 to the end of 2017 (Amatrice, Visso, Norcia, Campotosto), and era B, 2009 (L'Aquila).
These are the sequences anyone would ask a model about, so a model must never have seen them. One GNSS
station in ten is held out too, chosen by a hash so nobody picked the easy ones.

**3. A split is a set of files, and the files get checked.** The training data is cut from the snapshot
and written to disk, every file named by its hash. `craton bench leaks` reads all 2.5 million training
tokens back and fails if a single one is inside a held-out era, from a held-out station, or one of the
test's answers. "We filtered it" is a claim. Reading every file back is a check.

**4. Forecasts only see the past.** CB-02 asks for a forecast every midnight for the next day. The model
is fitted only on data from before 24 August 2016. Each morning it may read every quake that happened
up to midnight, because a real forecaster has those. It may not read anything after. This is called
*pseudo-prospective*: as close to a real forecast as you can get without waiting for the future.

**5. Scores are in bits.** Every answer is a probability, never a single number. The score asks how much
probability you put on what actually happened, as −log2(p). Put probability 1/8 on the truth and it
costs 3 bits; put 1/1000 and it costs about 10. The lower the cost, the less surprised the model was.
An LLM's perplexity is this same number, for words.

**6. Masking has to hide the whole answer.** In CB-01 a GNSS measurement is hidden and must be guessed
back. The first draft hid only the value (east, north, up). But a GNSS token's latitude and longitude
are that day's own position, precise to a millionth of a millimetre: the answer was still sitting in the
coordinates. So the position is hidden too, and only the station's site to 0.01° (about a kilometre)
is shown. Same for earthquakes: the tide token computed at a quake sits at the quake's epicentre, so it
is hidden with it. Leaks hide in the places you didn't think of; the test design has to go looking.

**7. Data has potholes, and the benchmark finds them.** The first CB-04 run gave an error of 22 metres.
The cause was the data: the Nevada Geodetic Laboratory reuses a few station codes for different sites.
MIR2 "moves" 595 km north in a day. The rule now: a station is one monument only if it never jumps more
than 1 m between two days. The biggest real jump in the region is ARQT's 0.447 m, in the Norcia
earthquake. Eight codes fail it. With them out, the error drops to 17.8 mm.

## The LLM analogy

| LLM world | Craton |
|---|---|
| Held-out test set (MMLU, HellaSwag, …) | the two eras and the held-out stations |
| Contamination check (is the test in the training data?) | `craton bench leaks`, reading every shard |
| lm-eval-harness | `craton bench run` + the task registry |
| Perplexity, bits per byte | CB-01, bits per masked token |
| "Beat the n-gram baseline" | beat climatology, Poisson, ETAS, IDW |
| A benchmark version (MMLU vs MMLU-Pro) | a new task ID; old IDs never change |

Where it breaks: a language model's test text is the same in 2016 and in 2026. An earthquake test has a
direction in time. Training on 2018 to forecast 2016 is a leak even if no 2016 token is in the data,
because 2018's aftershocks are the end of 2016's story. That's why the forecast tasks have their own
splits, cut at the start of their test window.

## What the code does

In the order a run flows:

1. `craton/bench/splits.py` — the eras, the held-out station rule, the three splits, cutting shards and
   the leak check.
2. `craton/bench/tasks.py` — the four tasks: what each hides, its test files, its fingerprint, how it
   scores. Also the three protocols a method implements (`MaskedPredictor`, `Forecaster`, `GapFiller`)
   and `register_task`.
3. `craton/bench/dists.py` — distributions as answers: anything with a `mass(lo, hi)`.
4. `craton/bench/csep.py` — gridded forecasts and the CSEP tests, matched against pyCSEP.
5. `craton/bench/etas.py` — the ETAS model: likelihood, fit, simulation, daily forecasts.
6. `craton/bench/baselines.py` — the four baselines and `register_method`.
7. `craton/bench/harness.py` — prepare, freeze, verify, run.
8. `craton/bench/frozen/central_italy.json` — the frozen record: snapshot, held-out stations, split
   manifests, every task's fingerprint and file hashes. Committed; rebuilding must reproduce it.
9. `craton/bench/cards.py` — renders `docs/bench.md`, the benchmark card.

| Task | Method | Score | In plain words |
|---|---|---|---|
| CB-01 Geo-perplexity | climatology | 22.7 bits ↓ | a masked quake costs 22.5 bits, a masked GNSS day 22.8 |
| CB-02 Apennines 2016-17 | ETAS | −7.12 bits ↑ | 7.5 bits per quake better than ignoring aftershocks |
| | Poisson | −14.64 bits ↑ | the long-run rate, spread like the long-run map |
| CB-03 L'Aquila 2009 | ETAS | −9.40 bits ↑ | the same lead over Poisson, fitted on four quiet years |
| | Poisson | −16.94 bits ↑ | |
| CB-04 GPS gap-fill | IDW + trend | 17.8 mm ↓ | most stations within 2-8 mm; a few near the ruptures far worse |

What they say:

- **Aftershocks are most of the story.** ETAS's 7.5-bit lead per quake over Poisson means it puts about
  180 times more probability on what actually happened (2^7.5). Knowing that quakes cluster is worth
  more than anything else a simple model can know.
- **Even ETAS is surprised.** Over the test window it expected 583 M3+ quakes and 1,065 happened. Most of
  the gap is the Visso and Norcia days: nothing in the past said a magnitude 6.5 was coming on
  30 October. On 4% of the days the observed count is too high for a Poisson forecast to have
  allowed it. That's the sequence being burstier than the model, and it's the gap Craton aims at.
- **Small quakes are where the information is.** At M1.5+, ETAS scores −2.76 bits per quake and Poisson
  −9.69. Thousands more quakes, each easier to place, because each sits near the last ones. P4's
  transformer reads exactly this.
- **L'Aquila is harder.** Fitted on 2005-2008 only (before 2005 the catalogue uses a different magnitude
  scale), ETAS comes out *supercritical*: each quake triggers on average 1.26 more. A real process like
  that would never stop. The forecasts stay finite because each one covers only a day, but it's a
  warning that four years of mostly quiet data don't pin the model down.
- **GPS between stations is smooth, except across a fault.** Most hidden stations are rebuilt to a few
  millimetres. The worst, like VCRA, sit where the 2016 ruptures broke the ground: their neighbours moved
  differently from them, and averaging neighbours can't know that. A model that knows where the faults
  are should win here.
- **Climatology's 22.7 bits** is the price of knowing nothing about context: where quakes usually are and
  how big they usually come, and where a station usually sits. A model that reads the visible 85% of the
  era should cut this a lot.

## Try it yourself

```console
uv run craton bench list                 # the tasks and which methods can run them
uv run craton bench prepare              # cut the splits, write the test files, compare with the frozen
uv run craton bench leaks                # read every training shard back
uv run craton bench run idw_trend        # 30 s; writes results/pending/
uv run craton ratchet                    # judge it against the board
```

Then make the baseline worse on purpose: set `neighbours=1` in `IdwTrend` (`craton/bench/baselines.py`),
run it again, and watch `craton ratchet` call it a regression.

## Check yourself

<details><summary>1. Why are the forecast tasks fitted only on data before their test window, when CB-01 isn't?</summary>

A forecast is about the future. Data from 2018 contains the end of 2016's aftershock sequence, so a model
fitted on it has seen how the story ends. CB-01 asks to fill holes inside an era, given the rest of the
era, which is a different question: no future is involved.
</details>

<details><summary>2. Why can't CB-01 hide only a GNSS token's value?</summary>

Because the token's latitude and longitude are the same day's position at sub-millimetre precision. The
answer would be in the coordinates.
</details>

<details><summary>3. ETAS scores −7.12 and Poisson −14.64 bits per quake. What is ETAS's information gain, and what does it mean?</summary>

7.52 bits per earthquake: on average ETAS gave each observed M3+ quake about 2^7.5 ≈ 180 times more
probability than Poisson did.
</details>

<details><summary>4. A new model scores −9.0 on CB-02. Can it go on the scoreboard?</summary>

Yes, in Craton's lane: it's the first Craton score, so it's "new". The scoreboard will show it 1.9 bits
below the floor (ETAS), plainly. Negative results are results.
</details>

<details><summary>5. Why does one held-out station near Norcia score badly for every neighbour-averaging method?</summary>

The 2016 ruptures moved stations on either side of the faults by different amounts, up to 45 cm. A
station's neighbours can be on the other side of a fault. Averaging them gives a jump the station never
made.
</details>

## Glossary

- **Held-out set** — data no model may train on, kept for testing.
- **Leakage / contamination** — test information reaching training, which makes a score meaningless.
- **Pseudo-prospective** — a forecast test on past data, fitted only on what came before the test.
- **ETAS** — Epidemic-Type Aftershock Sequence: every quake can trigger more, fewer as time passes
  (Omori's law) and more for bigger quakes.
- **Branching ratio** — the average number of direct aftershocks per quake; above 1, a sequence never ends.
- **CSEP** — the Collaboratory for the Study of Earthquake Predictability, which sets how forecasts are
  tested: gridded forecasts, Poisson likelihoods, the N, S and M tests.
- **N-test** — was the forecast's total count plausible?
- **Information gain per earthquake** — the difference of two forecasts' log-likelihoods per observed
  quake, in bits.
- **Inverse-distance weighting (IDW)** — averaging neighbours, closer ones counting more.
- **Fingerprint** — the hash of a task's definition, metric and test files; a different fingerprint is a
  different task.
