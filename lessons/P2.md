# P2 — First data: adapters and an immutable store

## TLDR

P1 built the shape. P2 pours real data into it: every earthquake INGV located in central Italy since 1985,
every day of every GNSS station there, and the solid-Earth tide at the moment of each quake.
Each source gets an **adapter**: download once, keep the raw bytes forever under their own hash, turn them
into validated tokens, and describe the data honestly in a **data card**.
Build twice from the same downloads and you get the same bytes, and the same snapshot name, every time.

Central Italy, January 1985 to September 2026: **1,758,860 tokens**. 320,757 earthquakes, 751,394
station-days from 293 GNSS stations, 686,709 tides. Snapshot `96a163f798d8f9cc`, the same on every rebuild.

## The idea, step by step

**1. Pretraining data is a pipeline, and the pipeline is half the model.** Every LLM lab will tell you the
same thing: the model is mostly its data. Before GPT reads a single word, a pipeline crawls, cleans,
deduplicates, filters and shards. Craton's version of that pipeline starts here, small enough to read.

**2. One adapter per source, and it's the only code that knows the source's quirks.** INGV writes a
pipe-separated table with depths below sea level. The Nevada Geodetic Laboratory writes longitude
13.2° E as −346.8 and measures east from a reference meridian. After the adapter, none of that exists:
everything downstream sees tokens. A new source is a new adapter, and nothing else changes.

**3. Three verbs.**

| Verb | Does | Touches the network? |
|---|---|---|
| `fetch` | downloads raw files and stores them by hash | yes, politely, once |
| `tokens` | turns raw files into validated tokens, one year at a time | no |
| `card` | says who made the data, the licence, how to cite it, what's wrong with it | no |

Splitting fetch from build matters. A build never asks the internet anything, so it gives the same answer
on Tuesday as on Monday.

**4. Raw bytes are sacred.** Every download is stored exactly as the server sent it, named by its sha256.
Every token's `provenance.content_hash` is that hash. So from any token in the model's training data you
can walk back to the exact bytes INGV or NGL served, and anyone can check the bytes haven't changed. When
INGV revises a month (it does), the new bytes get a new hash and a new manifest line; the old file stays.
Data is never overwritten, only versioned.

**5. A snapshot is a whole dataset, named by its content.** A build writes one JSON file listing every token
file and every raw file it used, with their hashes, and names that file by the hash of its own content.
Same downloads → same tokens → same snapshot name. "Is this the same data?" becomes "is this the same
16 characters?". P3 freezes its train/test splits against a snapshot.

**6. Refuse, count, never guess.** A catalogue line with a magnitude type the spec doesn't know is refused
and counted under `magnitude_type:<type>`. It is not mapped to the nearest known type. The health report
lists every reason with its count, so a silent data problem has nowhere to hide.

**7. The catalogue doesn't see everything, and how much it misses changes.** Small earthquakes are far more
common than big ones (Gutenberg–Richter: ten times more for every magnitude step down). So the number of
recorded quakes should keep rising as you go smaller... until the network can't detect them anymore, and
the count falls off. The magnitude where it peaks is the **magnitude of completeness**, Mc. Above Mc the
catalogue is complete; below it, holes. Mc for central Italy was around 2.6 in 1985 and
around 1.1 in 2025, because the network got denser. A model that ignores this would "learn"
that the Earth got more active over forty years. It didn't; the ears got better.

**8. Tides are computed, not downloaded.** The Moon and the Sun stretch the whole planet: the ground under
Norcia rises and falls by up to 32 cm twice a day, and nobody feels it because everything rises
with it. The tide is pure physics, so Craton computes it with the IERS 2010 model (the one geodesists use
to correct GPS), at every earthquake's epicentre and moment, plus an hourly series for the quiet days.
Whether quakes prefer some tidal phases is one of the questions P5 and P8 can ask.

## The LLM analogy

| LLM world | Craton |
|---|---|
| Common Crawl, books, code dumps | INGV, NGL, the tide model |
| Crawler + cache | `fetch` + the raw store |
| Cleaning and filtering, with a reject log | `tokens` + `ctx.reject(reason)` |
| Deduplication | event IDs, one token per station-day, refusing duplicate tokens |
| Shards | Parquet token files, one per instrument and year |
| Dataset card ("Datasheets for Datasets") | the data card, generated from the adapter |
| A dataset version hash | the snapshot id |

Where it breaks: web text has no units, no location and no error bars, so LLM pipelines filter on quality
heuristics. Earth data comes with physics attached, and the pipeline keeps it: magnitude types never mix,
uncertainty always travels with the value, the licence travels with every token.

Another break: in LLM data, a duplicate is the same text twice. Here the same quake can appear twice with
different numbers (two agencies, two magnitude types). P2 only removes exact repeats inside one source;
matching the same event across sources is a later problem.

## What the code does

In the order data flows:

1. `configs/regions/central_italy.yaml` — the box (41–44 °N, 11.5–15 °E), the window
   (1985 → 1 October 2026, fixed), the three adapters.
2. `craton/adapters/http.py` — a polite client: one request per second per host, a User-Agent that says who
   is asking, back-off on server errors.
3. `craton/store/raw.py` — the raw store: files by hash, one append-only `manifest.jsonl` per source.
4. `craton/adapters/base.py` — `Adapter` (`fetch`, `tokens`, `card`), `DataCard`, `BuildContext`.
5. `craton/adapters/ingv.py` — the catalogue month by month. The service refuses more than 20,000 events
   per request; a month that busy is fetched in halves and joined.
6. `craton/adapters/ngl.py` — the station list, then each station's daily series, bucketed by year so only
   one year of tokens is in memory at a time.
7. `craton/geo/` — frames (lat/lon ↔ Earth-centred metres), clocks (UTC → TT, leap seconds), the Sun and
   the Moon, and the IERS tide itself.
8. `craton/adapters/tides.py` — reads the catalogue tokens of the same build, computes a tide at each.
9. `craton/adapters/build.py` — runs the adapters in dependency order, writes token files, the snapshot
   and `results/data_health.json`.
10. `craton/adapters/health.py` — the numbers: counts, rejects, Mc per year, station gaps, tide peaks.
11. `craton/adapters/cards.py` — renders `docs/data/` from the adapters; `craton check` keeps it in sync.

| Source | Tokens | Refused | What it says |
|---|---|---|---|
| INGV catalogue | 320,757 | 126 | Norcia Mw 6.5 is the largest; the longest stretch with no quake in the box is 10.9 days |
| NGL GNSS | 751,394 | 0 | 293 stations, the first from 1995; median 1,927 days each, 83% of days present |
| Body tide | 686,709 | 0 | one at every earthquake + one every hour; up to 31.9 cm up and down |

What the numbers say, in plain words:

- **The 126 refusals are all honest.** 120 events carry a magnitude type of just "M" (114 of them from
  2009-2012, with author `UNKNOWN`); Craton doesn't know which scale that is, so it won't pretend. 5 are controlled explosions
  and 1 is an "anthropogenic event": not earthquakes.
- **The magnitude scale changed under our feet.** Until 2004 INGV reported duration magnitude (Md: how long
  the shaking lasts on the record); from 2005, local magnitude (ML: how big the wiggle is). 29,466 Md, 290,892
  ML, 399 Mw. They stay separate, and completeness is measured for each.
- **The catalogue jumps in 2005**, from about 60 events a month (2004) to about 250 (2006). That's when INGV's
  modern processing begins, and smaller quakes start being located. Earthquakes didn't change; the
  catalogue did. P3's splits have to respect that.
- **The spikes are real.** Colfiorito (1997), L'Aquila (2009) and the 2016 Amatrice-Visso-Norcia sequence
  are visible as months with thousands of events; November 2016 holds 13,209.
- **GNSS arrives late.** One station in 1995, more than a hundred from 2009. Anything Craton learns from GPS
  is about the last fifteen years.
- **Reproducible.** Two full builds from the same 795 raw files gave the same 115 token files and the same
  snapshot id. The tide code matches the IERS test cases to 1e-12 m, PySolid to 0.4 mm and the JPL
  ephemeris to 0.7 mm.

## Try it yourself

```console
uv run craton data list                    # adapters, licences, regions
uv run craton data fetch central_italy     # once: a few hundred MB, polite, cached
uv run craton data build central_italy     # offline; prints the snapshot id
uv run craton data build central_italy     # again: same id
```

Then open a token file: `uv run craton spec validate data/tokens/instrument=seismic_catalog/year=2016/<file>.parquet`
re-checks every token and its file hash. Or compute a tide yourself:

```python
from craton.geo import solid_tide_enu
from craton.spec.timeaxis import to_seconds

solid_tide_enu(42.78, 13.10, to_seconds("2016-10-30T06:40:17Z"))  # east, north, up in metres
```

## Check yourself

<details><summary>1. Why doesn't <code>craton data build</code> touch the network?</summary>

So a build depends only on the raw files, which are named by their hashes. Same raw files, same tokens,
same snapshot id. A build that downloads could give a different answer every day.
</details>

<details><summary>2. The catalogue has about eighty times more events in 2016 than in 1990. Did the Earth get busier?</summary>

Partly (2016 had the Amatrice–Norcia sequence), but mostly the network got better: the magnitude of
completeness dropped, so smaller quakes got recorded. Comparing counts across years only makes sense above
the worst year's Mc.
</details>

<details><summary>3. Why is NGL's licence a <code>LicenseRef-</code> and not CC-BY-4.0?</summary>

Because NGL doesn't state a licence. Its terms are "supplied as-is, please cite". Writing CC-BY-4.0 would
put a claim the provider never made into hundreds of thousands of tokens.
</details>

<details><summary>4. Why compute tides at earthquakes and not every day at every GNSS station?</summary>

NGL's daily positions already have the body tide removed, and a daily average of a twice-a-day wave is
nearly zero. The tide matters at the moment a fault slips.
</details>

<details><summary>5. INGV revises last month's catalogue. What happens to Craton's data?</summary>

On `fetch --refresh`, the new bytes get a new hash and a new manifest line; the old file stays. The next
build makes new tokens with new content hashes and a new snapshot id. Nothing old is overwritten.
</details>

## Glossary

- **Adapter** — the code that turns one source into tokens.
- **Raw store** — downloads kept exactly as served, named by sha256.
- **Snapshot** — a list of every token and raw file in a build, named by its own hash.
- **FDSN** — the International Federation of Digital Seismograph Networks; its web services are how
  seismological data centres share catalogues and waveforms.
- **ISIDe** — INGV's Italian Seismological Instrumental and Parametric Database, 1985 to today.
- **GNSS daily solution** — one position per station per day, from 24 hours of satellite signals.
- **IGS20** — the reference frame the positions are expressed in (the IGS's version of ITRF2020).
- **Magnitude of completeness (Mc)** — the smallest magnitude a catalogue records reliably.
- **Maximum curvature** — estimating Mc as the most common magnitude (plus 0.2, a known correction).
- **Solid-Earth (body) tide** — the elastic stretching of the whole Earth by the Moon and the Sun.
- **Love and Shida numbers** — how much the Earth deforms up (h) and sideways (l) under a tidal pull.
- **Terrestrial Time (TT)** — the smooth clock astronomy runs on: UTC + leap seconds + 32.184 s.
