# P1 — The universal token

## TLDR

Before a model can learn from the Earth, everything the Earth tells us has to arrive in one shape.
P1 defines that shape: **Token Spec 1.0.0**, ten slots that fit an earthquake, a GPS day, the pull of
the Moon, a rock's porosity and a monk's account from 1349.
A strict validator refuses anything malformed, with a named reason. The spec is now frozen: from here on
it can only grow.

## The idea, step by step

**1. What a tokenizer actually did for language.** Before GPT, text came in a thousand formats: tweets,
books, code, chat logs. The tokenizer turned all of it into one thing, a list of integers from one
vocabulary. After that, one model could read everything. That boring step is why "read the whole
internet" became possible.

**2. Geology never had that step.** A seismic catalogue is a table of quakes. A GNSS station is a file of
daily positions. A rock lab reports porosity. A historian reads a chronicle. Four formats, four
communities, four models that never read each other.

**3. So: one shape for everything.** Every measurement on Earth becomes:

| Slot | Says |
|---|---|
| `kind` | observation, forcing, property, event or derived |
| `instrument` | what measured it; the registry says what the numbers mean |
| `lat`, `lon`, `depth_km` | where |
| `time` | when |
| `value` | the numbers |
| `uncertainty` | how much to trust each number |
| `qualifiers` | labels: magnitude type, station code, intensity scale |
| `provenance` | who published it, which version, which licence, the hash of the raw bytes |
| `resolution` | how big a patch of space and time one value describes |

**4. The uncertainty slot is the whole trick.** On 9 September 1349 an earthquake devastated
Montecassino Abbey. The monks wrote it down; centuries later seismologists read those accounts and
assessed intensity 9 on the Mercalli–Cancani–Sieberg scale. On 31 October 2016 the GNSS station ARQT,
10 km from the Norcia epicentre, reported its position to under a millimetre horizontally.

Same shape. The monk's token says "± half a degree of intensity, *assumed*"; the receiver's says
"± 0.7 mm, *reported*". A model that reads both learns to lean on the receiver and still listen to the
monk, who is the only sensor we have for 1349. Without the slot it would treat them as equally sure,
which is how you get a confident, wrong model.

That's why uncertainty is **required** and can **never be zero**. Nothing is measured perfectly, and a
token that claims otherwise is refused.

**5. The monk lived in a different calendar.** 1349 predates the Gregorian calendar (1582). His
"9 September" was a Julian date; on Craton's clock it is 17 September. If every medieval token were
filed eight days early, a model looking for patterns in time would learn the error. So the spec has one
clock, proleptic Gregorian seconds since 1970, and converting old dates is the adapter's job, done once,
tested.

**6. One float covers seconds to eons.** `time` is a single number. For 2016 it's precise to well under a
microsecond; a billion years ago it's still precise to about a minute. The same axis serves a seismogram
in P4 and a plate reconstruction in P11.

**7. Where "down" starts.** Depth is measured from the WGS84 ellipsoid, the mathematical surface GPS uses.
ARQT sits 1.66 km above it, so its depth is −1.66 km. Sea level would have been friendlier, but it depends
on which model of the geoid you pick; the ellipsoid is one exact surface everywhere.

**8. Resolution vs uncertainty.** Different things. The Norcia hypocentre is known to about 200 m: that's
uncertainty. It's also the point where the rupture *started*; the rupture itself was ~30 km long: that's
what a different token, with a different resolution, would describe. The monk's report is dated to the day,
not the hour, so its time slot is a whole day wide.

**9. Frozen means frozen.** Tokens written today must be readable forever. So the spec only grows:

- new instruments, new vocabulary words, new *optional* fields: fine (a minor version);
- removing, renaming, changing a unit or a range: refused. Want something different? Register a new
  instrument with a new name.

A snapshot of spec 1.0.0 sits in `craton/spec/frozen/1.0.0.json`, and `craton check` compares the code with
it on every change. The building analogy again: you can add floors, you can't swap the concrete in the
basement.

## The LLM analogy

| LLM world | Craton |
|---|---|
| Tokenizer | adapters (P2) that turn raw files into tokens |
| Vocabulary | the instrument registry |
| A token ID | a token: one measurement, with its place, time and trust |
| Vocabulary frozen after pretraining | the spec frozen after release, add-only |

Where it breaks: an LLM token is just an ID; its meaning is learned. A Craton token arrives with
meaning already attached (units, place, time, uncertainty). That's more structure than language ever had,
and the model should use it instead of rediscovering it. The encoders in P4 turn these slots into vectors.

Another break: LLM vocabularies are fixed at training time. Craton's registry keeps growing while old tokens
stay valid, which is closer to how Unicode adds characters without breaking old text.

## What the code does

In the order a measurement flows:

1. `craton/spec/registry.py` — `Channel`, `Qualifier`, `Instrument`, `Registry`. An instrument declares its
   channels (name, unit, range), kinds and labels. Registering a changed definition under an old name raises.
2. `craton/spec/instruments.py` — the 11 instruments of spec 1.0.0: earthquakes, intensity reports, GNSS,
   solid-Earth tides, and six rock properties (porosity, permeability, grain size, lithology, temperature,
   friction), plus the Gutenberg–Richter b-value as a derived token.
3. `craton/spec/timeaxis.py` — the clock: ISO ↔ seconds, Julian → Gregorian, the year of any time.
4. `craton/spec/token.py` — the `Token` model. It validates itself against the registry when created, so an
   invalid token can't exist. Every failure has a code: `lat_range`, `uncertainty_nonpositive`,
   `missing_qualifier`… `validate_token()` turns them into a `TokenError` listing every problem.
5. `craton/spec/sequence.py` — checks that need many tokens: time order and duplicates.
6. `craton/store/parquet.py` — tokens into Parquet files under `instrument=…/year=…/`, each named by its own
   hash. Same tokens, same bytes, same name, so files can't be edited in place.
7. `craton/spec/policy.py` and `craton/spec/frozen/` — the add-only check.
8. `craton/spec/examples.py` — one example per kind. Three come from raw records quoted in the code and
   hashed; the others are labelled illustrative.

## The numbers

No CratonBench score moves in P1; the benchmark here is the validator suite.

- **72 malformed tokens**, each built by breaking one thing in a valid example, each refused with the
  expected code. A few favourites: longitude −346.8 (how the Nevada lab writes 13.2° E), magnitude 11,
  intensity 13 (the scale stops at 12), a GPS station in lowercase, "Creative Commons BY" as a licence
  (not an SPDX code), spec version 1.99 (a future this code can't read).
- **11 example tokens**, all valid, one or more per kind.
- Writing the same tokens twice gives **byte-identical** files.

One real number from the examples: ARQT's daily position dropped **0.447 m** between 29 and 30 October
2016. That's the Norcia earthquake, measured by the ground moving under an antenna.

## Try it yourself

```console
uv run craton spec                                # the slots and the 11 instruments
uv run craton spec example montecassino_1349      # the monk, as JSON
uv run craton spec example arquata_gnss > t.json  # then break t.json and:
uv run craton spec validate t.json                # every problem, with its code
```

Try setting `"uncertainty": [0]` and watch it refuse. Then try `"lon": 193.2`.

## Check yourself

<details><summary>1. Why is uncertainty required, and why not zero?</summary>

So the model knows how far to trust each source. Zero would claim a perfect measurement, which doesn't
exist, and would make the model over-trust that token.
</details>

<details><summary>2. The monk's earthquake was on 9 September 1349. Why does the token say 17 September?</summary>

His date is in the Julian calendar. Craton's clock is Gregorian everywhere, and in the 14th century the two
differ by 8 days.
</details>

<details><summary>3. You want GNSS velocities in mm/yr. Do you add channels to `gnss_daily`?</summary>

No: frozen instruments never change. Register a new instrument (say `gnss_velocity`) in a minor version.
</details>

<details><summary>4. What's the difference between `resolution` and `location_uncertainty`?</summary>

Resolution is how big a patch of space and time one value describes. Location uncertainty is how well we
know where and when that patch is.
</details>

<details><summary>5. Why name token files by their own hash?</summary>

Different bytes can't have the same name, so a file can't be silently edited, and anyone can check a
file by recomputing its hash.
</details>

## Glossary

- **Token** — one measurement in the universal shape.
- **Instrument registry** — the vocabulary: which instruments exist and what their numbers mean.
- **Channel** — one number in a token's value, with a name, unit and range.
- **Qualifier** — a text label a token carries (magnitude type, station code).
- **Macroseismic intensity** — how strongly an earthquake was felt at a place, read from damage and
  accounts, on a 1–12 scale (MCS, EMS-98).
- **WGS84 ellipsoid** — the smooth reference surface GPS measures height from.
- **Julian / Gregorian calendar** — the old and current calendars; they drifted apart by about 3 days every
  4 centuries.
- **UCUM** — a standard list of unit codes (`m`, `Pa`, `Cel`).
- **SPDX** — a standard list of licence codes (`CC-BY-4.0`).
- **Semantic versioning** — MAJOR.MINOR.PATCH; here, minor versions only add.
- **Content-addressed** — named by a hash of its own bytes.
